# Tyr Governance

---

## Purpose

This document defines how decisions are made within The Tyr Project.

The goal is to ensure that Tyr evolves through technical discussion, consensus, and careful review rather than rapid or inconsistent changes.

---

# Core Principles

The Tyr Project values:

- Technical excellence
- Constructive discussion
- Openness
- Long-term stability
- Respectful collaboration

---

# Project Leadership

The project is maintained by the Core Maintainers.

Core Maintainers are responsible for:

- Language evolution
- Compiler architecture
- Release management
- Repository maintenance
- Reviewing RFCs

---

# Language Changes

No language feature should be implemented before it is specified.

Every significant language change follows this process:

1. Proposal
2. RFC discussion
3. Community feedback
4. Maintainer approval
5. Specification update
6. Compiler implementation

---

# Compiler Development

The compiler implements the language specification.

The specification always takes precedence over implementation.

Compiler behavior should never redefine the language.

---

# Releases

Language releases and compiler releases are versioned independently.

The language specification defines the standard.

The compiler provides one implementation of that standard.

---

# Decision Making

Whenever possible, decisions should be made through consensus.

When consensus cannot be reached, the Core Maintainers make the final decision based on the project's long-term goals.

---

# Contributors

Everyone is welcome to contribute.

Contributions may include:

- Documentation
- Compiler development
- Testing
- Examples
- Tooling
- Language proposals

---

# Our Goal

Our goal is not to build the largest language.

Our goal is to build a language that remains elegant, predictable, and useful for decades.
